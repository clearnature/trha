# 验证判据（verification criteria）

> **日期**：2026-09-13（北京时间）
> **来源**：所有者对一次错误实践的纠正 —— 我把 GF(27) 实现的验证降级成 benchmark 比拼，
> 并用 107 ms vs 16 ms 这类**与环境绑定**的数字"否证"了一个方向。**判据错了，结论就无意义。**

---

## 0. 一句话

**判据是数学与理论的正确性，不是硬件性能。**

> 所有者原话要点：本地 CPU 的性能在本机 GPU 上被打成渣，本机 GPU 在其他服务器上又被打成渣；
> 追求计算速度是可笑的方向。我们要的是**强类型的数学正确性**与**因果推理内核**。

性能是**环境标量**（机器、驱动、负载、库版本一变就变），拿它当判据等于没有判据；
它只能作为**参考记录**。

---

## 1. 判据清单（按优先级）

| # | 判据 | 可执行形式 |
|---|---|---|
| **C1** | **代数结构正确** | 域公理（单位/零/交换/分配/逆元）、乘法群阶、与**权威规范**（Agda `GF9.agda` / `GF27.agda` / `GF81.agda` / `LCM.agda` / `Zhonglv`）**全量**对拍 |
| **C2** | **类型不变量成立** | 强类型句柄不可混用（负面测试必须**编译失败**）、范畴隔离（`Trit` / `GF9` / `GF27` / `Z3r` 各是各的） |
| **C3** | **多实现逐元素全等** | 同一数学结构的不同实现（Haskell 标量 / C 标量 / AVX2 / GPU WGSL）在**同一批输入**上结果全等 —— 这才是"跨硬件一致"的证据 |
| **C4** | **因果推理语义可验证** | `t6Verify` / `causalGraphStep` / `wuxingForward` / `tailCycle` 的**语义**（相位连续、可达、不落不动点）而非吞吐 |
| **C5** | **与外部 API 推理的约束关系**（D-1，未落地） | 约束**作用于**外部推理（而非只作用于本地前向） |

**性能（fps / ms / token-s、显存、带宽）不在判据之列**，只作附录记录，且必须标注测量环境。

---

## 2. 由此产生的纪律

1. **禁止**用 benchmark 结果判定方案成败；**更禁止**据此否决方向或删除实现。
2. 一个实现"慢"**不构成**移除它的理由 —— 它可能是唯一的异构一致性与可移植性证据。
3. 新增算力实现（CPU SIMD、GPU kernel、别的加速器）时，**先交对拍与结构一致性**，
   性能数据后置且标注为参考。
4. 说"完成"必须以 C1–C4 的**可执行证据**为准（对拍输出、负面编译、测试计数），
   不以"跑得更快"为准。
5. 跨硬件差异（本机 vs 服务器 vs CI）**不得**进入正确性结论。

## 3. 本次错误的复盘（留档，避免重蹈）

| 环节 | 我做的 | 应该做的 |
|---|---|---|
| 定位 | 把 SIMD/BLAS 当"性能优化任务" | 视作"数学结构的另一实现"，用于 C3 |
| 判据 | 用 `107 ms vs 16 ms` 判成败 | 用 C1/C2/C3：四实现是否逐元素全等 |
| 决策 | 以"慢"为由**否决**方向、不接线 | 慢只入附录；接线与否是**工程选择**（真链稳定性），与数学正确性无关 |
| 叙述 | 提交信息写"性能否证、不接线" | 写"BF(27) 四实现一致（Haskell/C/AVX2/GPU），结构跨实现成立" |

**事实仍然保留**：AVX2 版本机确实慢于标量（原因是 `i32gather` 为微码 + 乘法表仅 27 项驻留 L1）
—— 这条**记录**有价值，但它**不是结论**，更不是否决理由。
